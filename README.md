I build the web applications people actually transact on, and I write the tests behind them.

For the last three and a half years that was **Wawa**: React and TypeScript features for web ordering, catering and the in-store kiosk across a chain of more than 1,000 stores. I helped shape the Playwright and Cucumber BDD framework early on, then built the scenarios that took feature coverage to 100% across catering and web ordering, surfacing 15 latent defects that unit tests had missed.

Before that I spent six years as UI Technical Lead on **Chase Ultimate Rewards** through **Bridge2Solutions**, setting technical direction for 4 onshore and 16 offshore developers through influence rather than reporting authority, and setting W3C/ADA AA accessibility standards across the platform. I also built an internal UX/UI debugging tool the team used daily; it raised development efficiency 60 to 80%. In between I consulted for **Cox Communications**.

Since 2021 I've run **S24DeFi Labs**, an independent product studio. Claude Code, ChatGPT and GitHub Copilot are daily tools, with an AI-assisted review step in front of every merge and a person making the final call.

### Now building

- **algo_bot**: a co-built, paper-first trading research platform where safety controls come before strategy.
- **Stewards.Digital**: AI-assisted website audits and rebuilds for non-profits, live.

## How I work

**Testing is part of the feature, not a phase after it.** A Playwright or Cucumber scenario ships with the component. Coverage numbers are a side effect; the goal is that a regression gets caught before a customer finds it.

**Tooling is a product.** Internal tools get the same treatment as customer-facing ones: a real README, tests, and someone measuring whether they helped. The debugging tool on the Chase Ultimate Rewards contract earned its place because we measured the difference it made.

**AI in the loop, with a person making the final call.** Claude Code, ChatGPT and Copilot help me write and refactor every day. A structured AI review runs before human review on every PR. Nothing merges on the model's say-so alone.

**Accessibility is a requirement.** I set and championed W3C/ADA AA standards across an enterprise Angular platform: contrast, semantics, ARIA, full keyboard navigation. Mission Next runs a WCAG 2.2 AA check in CI. "Works for everyone" is scoped in, not bolted on.

## Security and reliability practices

The trading platform is where these habits were tested hardest, because a bug there costs real money. The same rules apply to everything I ship.

- **Every door is locked.** Every API and live connection requires a valid token, only approved websites can call in, and sessions can be checked individually when needed.
- **Secrets never reach the client.** Environment-driven configuration, `.env` files gitignored from the first commit, and a hard rule that no credential is ever committed to client source. History gets scanned before a repo goes public.
- **Safe by default.** Real-money trading, production deploys, and anything destructive are off until someone deliberately turns them on. An emergency stop can be triggered by a file, a setting, or the command center.
- **Everything is on the record.** Every automated yes and no is written to a log that can be added to but never edited, so any decision can be traced back after the fact.
- **Third-party code is checked.** Every build scans the packages the project depends on, alongside lint, type checks, and tests. Public repos carry a `SECURITY.md` and Dependabot.
- **Measure before something breaks.** Prometheus, Grafana, and Alertmanager on the trading platform; Datadog on production commerce. If it can wake someone up at night, it should already be on a dashboard.
